## 5. Assessment

### Where AI Added Real Value

- **End-to-End Cross-Layer Consistency:** Keeping PostgreSQL RPC parameter signatures, Deno Edge Function payload validation, and React frontend API calls synchronized across 6 Edge Functions and 1,700+ lines of transactional SQL would have been error-prone by hand; the AI accelerated cross-layer updates substantially.
- **Systematic Edge-Case Discovery:** During the pre-submission admin audit (`8e1eced`), using AI to cross-check implemented RPCs against RUP alternative flows (`UC-20 §2.2.3–2.2.4`, `UC-21 §2.2.4`, `EC-03`, `EC-12`, `EC-19`) surfaced subtle defects such as overdue-fine double charging and unreleased holds on damaged copies.
- **Fast CI Triage:** Feeding exact GitHub Actions error logs to the AI quickly narrowed down seed-data collisions and schema mismatches across parallel feature branches.

### Where AI Was Unreliable / Limitations

- **Silent SQL & Schema Errors Until Execution:** The AI generated syntactically plausible PL/pgSQL with subtle runtime bugs (e.g., an 8-value `INSERT` into a 9-column `receipts` column list, missing `FOR UPDATE` row locks, and UTC vs. `Asia/Ho_Chi_Minh` date truncation) that were only caught by running `supabase db reset`, pgTAP tests, and manual audits.
- **Overlooking Privilege & Re-Check Boundaries:** Initial drafts did not automatically enforce `REVOKE EXECUTE ... FROM authenticated` or re-check account/item state inside locked SQL transactions; I had to explicitly enforce the server-authoritative write pattern and verify it with `has_function_privilege` assertions.
- **Subtle React Lifecycle Bugs:** AI-generated modals and cross-tab links introduced state bugs (unrevoked `URL.createObjectURL` blob handles and stale `editing` flags after ISBN conflict resolution in `BookEditorModal.jsx`) that required manual browser testing and targeted code review to fix.
