## 5. Assessment

### Where AI Added Real Value

- **Rapid Figma-to-React Translation:** Translating 7 multi-state Reader screens (including responsive card grids, bottom-sheet variant picker, 2-step checkout stepper, and QR receipt card) into clean React + CSS components significantly accelerated UI delivery.
- **Deterministic Seed Authoring & Invariant Checking:** Building `seed-books.mjs` with built-in programmatic checks caught 10 subtle Vietnamese `hoa` substring collisions automatically before touching `seed.sql`, saving tedious manual debugging against `TS-08`.
- **Cross-Layer UC Auditing & Fast Environment Diagnosis:** Comparing 5 RUP Use-Case specs against both React and PL/pgSQL files quickly surfaced real spec gaps (pagination limit, 14-day non-member duration, 30-minute counter payment deadline, `v_copy` unassigned record), and inspecting Docker/GoTrue container state immediately pinpointed the Windows `winnat` port-exclusion range (`54238–54337`) and `GOTRUE_EXTERNAL_EMAIL_ENABLED=false`.

### Where AI Was Unreliable / Limitations

- **Implicit Assumption on Column Permissions & CSS Cascade:** Early AI output used `.select('*')` on `public.books` (triggering `42501` against the revoked `embedding` column and causing 404 on every book) and relied on default `<button>` styles that conflicted with `App.css`, both of which only showed up when I tested the app live in the browser.
- **Over-Scoping Without Explicit Boundaries:** Left unconstrained on an initial prompt, the AI also scaffolded extra Admin screens outside my assigned 4-screen boundary; I had to explicitly roll back unrelated screens to keep our team's branches clean.
- **Spec Edge Cases Missed in First Pass:** Initial drafts omitted pagination beyond 40 items, left a hardcoded `"Maya L."` fallback review, allowed non-members to toggle 14 days, and left `payment_deadline` at 30 minutes for counter checkouts—all of which required a dedicated UC-by-UC review pass to catch and fix.
