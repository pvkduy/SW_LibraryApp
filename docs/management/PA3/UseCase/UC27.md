## 1. Use-Case Name

**UC-27 - Review analytics and export reports** (Traces to: `FEAT-25`, `FR-ANLY-01`, `FR-ANLY-02`, `FR-ANLY-03`, `FR-ANLY-04`, `TS-54`, `TS-55`)

### 1.1 Brief Description

This use case allows a Librarian (Admin) to monitor library operations through the analytics dashboard and export structured administrative reports. The dashboard aggregates eight Key Performance Indicators (KPIs) — items on loan vs total stock, overdue count, damaged copies, Premium-loan revenue, fines collected, lost copies, membership revenue, and active reservations — plus a top-10 borrowed titles list and a monthly loans-trend-per-category chart. Staff export reports through a report center offering three preset modules — Circulation, Fines & Revenues, and Inventory — where the selectable option is a date range.

### 1.2 Actors

- **Primary Actor:** Librarian (Admin)
- **Supporting Actor:** Analytics & Reporting Engine (PostgreSQL RPC Functions & Export Formatter)

## 2. Flow of Events

### 2.1 Basic Flow

This use case begins when an authenticated **Librarian (Admin)** navigates to the Analytics Dashboard (`/admin/dashboard`) or Reports section (`/admin/reports`).

1. The **Librarian (Admin)** opens the "Analytics Dashboard" from the admin portal menu.
2. The **System** sets the default date range filter to the last 30 days (`30 days`).
3. The **System** invokes the database SQL RPC functions over indexed transaction tables.
4. The **System** renders the Dashboard with:
   - **Eight KPI Cards:** Items on loan (`borrowed` + `overdue`) vs total active stock; overdue count; damaged copies; Premium-loan revenue; fines collected; lost copies; membership revenue; and active reservations.
   - **Top-10 borrowed titles** for the range.
   - **One monthly loans-trend-per-category chart.** Nothing else is shown.
5. The **Librarian (Admin)** reviews the displayed metrics and chart.
6. The **Librarian (Admin)** closes the dashboard or navigates to other administrative tasks. The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 Change Analytics Date Range Preset or Custom Interval

_Branching point: At Step 4 of the Basic Flow, if the Librarian selects a different analytical timeframe._

1. The **Librarian (Admin)** selects a timeframe preset: "Today", "7 days", "30 days", or selects "Custom Range" to specify exact start and end dates.
2. The **System** validates that the start date precedes or equals the end date.
3. The **System** re-executes the analytics RPCs using the new date parameters.
4. The **System** updates all KPI figures, ranking tables, and category trend charts in place without a complete page reload.
5. The flow resumes at Step 5 of the Basic Flow.

#### 2.2.2 Configure and Export a Preset Report

_Branching point: At Step 1 or Step 5 of the Basic Flow, if the Librarian navigates to the dedicated Reports screen (`/admin/reports`)._

1. The **Librarian (Admin)** navigates to the "Reports" screen (`/admin/reports`).
2. The **System** presents exactly **three preset report modules**, each selectable by the Librarian: **Circulation**, **Fines & Revenues**, and **Inventory**.
3. The **System** exposes one customizable option for the selected module: a **date range** (preset or custom).
4. The **Librarian (Admin)** chooses the module, sets the date range, picks an output format (CSV, PDF, or Excel), and clicks "Export".
5. The **System** verifies that total rows do not exceed the threshold (`export_max_rows = 20,000`).
6. The **System** compiles the dataset, prepends the standardized audit header (`Generated By`, `Timestamp`, `Date Range`, `Row Count`), and delivers the downloaded file.
7. The flow resumes at Step 5 of the Basic Flow.

#### 2.2.3 Export Prevented Due to Row Count Limit

_Branching point: At Step 5 of Alternative Flow 2.2.2, if the query returns more than 20,000 rows._

1. The **System** detects that the dataset exceeds `export_max_rows` (20,000 records).
2. The **System** suppresses file generation and displays a warning: _"The requested report contains {N} records, which exceeds the maximum export limit of 20,000 rows. Please narrow your date range."_
3. The **Librarian (Admin)** shortens the date range.
4. The flow resumes at Step 4 of Alternative Flow 2.2.2.

#### 2.2.5 Handling Sparse or Empty Data Periods

_Branching point: At Step 3 of the Basic Flow or Step 3 of Alternative Flow 2.2.1, if no loan, payment, or inventory activity occurred within the selected window._

1. The **System** detects zero records for the selected date interval.
2. The **System** displays 0 for numeric KPI counters (e.g., `0 VND`, `0 loans`, `0 overdue items`) rather than error states or undefined values.
3. Ranking tables and charts display friendly contextual empty placeholders: _"No circulation activity recorded for this period."_
4. The flow resumes at Step 5 of the Basic Flow.

## 3. Special Requirements

### 3.1 Financial Calculation and Revenue Integrity

- Revenue figures displayed on dashboard cards and financial export reports must represent net signed sums computed from immutable `receipts` records (`DEC-41`).
- Reversals and refunds must be properly factored as negative amounts; if an initial 5,000 VND fee receipt is later reversed via a reversal receipt, the net revenue reflected for that transaction must be exactly 0 VND.

### 3.2 Performance and SQL RPC Execution

- High-level KPI aggregations must execute directly within PostgreSQL via optimized SQL stored procedures (`get_dashboard_kpis`, `get_rankings`) taking advantage of table indexes.
- Dashboard KPI load time must meet the system requirement of $p95 \le 1.0\text{ s}$ (`NFR-04`).

### 3.3 Role-Based Access Control

- All routes under `/admin/dashboard` and `/admin/reports`, along with underlying analytical Edge Functions and RPC endpoints, are strictly protected by RLS and role checks restricting access to users with `admin` metadata (`FR-AUTH-05`).

### 3.4 Report Internationalization

- PDF exports must embed Unicode fonts compliant with UTF-8 Vietnamese character encodings, ensuring correct visual display of diacritics in book titles, student names, and administrative terms.

## 4. Preconditions

### 4.1 Librarian Authentication

The Librarian has authenticated with valid staff credentials possessing the `admin` role.

### 4.2 System Health and Reporting Engine

The database instance is active, and circulation, inventory, and receipt tables are indexed and available.

---

## 5. Postconditions

### 5.1 Metrics Inspected

- The Librarian has inspected operational statistics and demand indicators.
- No database records are modified as a consequence of viewing analytics.

### 5.2 Audit Entry Generated for Sensitive Exports

- When a comprehensive report export containing financial or circulation data is dispatched, the system logs an audit entry recording the admin user ID, timestamp, report type, applied filters, and row count (`FR-SYS-03`).
