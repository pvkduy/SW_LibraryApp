## 1. Use-Case Name

**UC-14 - Reserve an unavailable book** (Traces to: `FEAT-16`, `FEAT-17`, `POL-07`, `FR-RES-01`, `FR-RES-04`)

### 1.1 Brief Description

This use case allows an eligible Student holding an active membership plan to place a reservation on a circulating book that currently has zero available copies on the shelf. The reservation places the student into an ordered, first-come first-served queue (up to a maximum queue depth of 5 members per title, with a maximum of 3 concurrent active reservations per student). When any physical copy of the title is subsequently returned or processed, the system automatically allocates the copy, changes the reservation status to `ready_for_pickup`, and initiates a 48-hour pickup window backed by notification dispatch. Members can track their position in queue or voluntarily cancel reservations without penalty.

### 1.2 Actors

- **Primary Actor:** Student (Reader)
- **Supporting Actor:** Authentication and email service (Notification delivery via In-App Realtime and SMTP/Email API)

## 2. Flow of Events

### 2.1 Basic Flow (Placing a Reservation)

1. The **Student** navigates to the Book Detail page (`/books/:bookId`) of a title where all copies are currently on loan, held, or under repair (`available_copies == 0`).
2. The **System** verifies the student's eligibility per policy `POL-07`:
   - Student has an active membership (`can_reserve = true` from membership snapshot).
   - Student has no debt hold (`debt_hold = false`) and no active reservation ban.
   - Student currently holds fewer than 3 active reservations.
   - The title is circulating (has at least one copy not `retired` or `lost`).
   - The book's waiting queue has fewer than 5 members (`queue_depth < 5`).
   - The student does not already have an active loan, cart request, or existing reservation for this book.
3. The **System** displays the "Reserve" button on the book detail card alongside the current queue length (e.g., "Queue: 2 waiting").
4. The **Student** clicks the "Reserve" button.
5. The **System** presents a confirmation dialog outlining the reservation policy:
   - Queue position to be assigned.
   - An explanation that once a copy becomes available, the student will have 48 hours to collect it.
   - A reminder that failing to collect within 48 hours incurs a reservation strike (3 strikes result in a 30-day reservation ban).
6. The **Student** confirms the reservation.
7. The **System** invokes the reservation transaction in PostgreSQL:
   - Assigns the next queue sequence number (`queue_position = current_max + 1`).
   - Inserts a new row in the `reservations` table with status `waiting`, timestamped with `created_at = NOW()`.
   - If the student previously had this book on their personal wishlist (`UC-08`), the system removes or flags the wishlist entry to prevent duplicate notifications.
8. The **System** displays a confirmation toast: _"Reservation placed successfully! You are #X in line."_
9. The **System** updates the UI to show the active reservation details and provides a quick link to the student's Reservations dashboard (`/reservations`). The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 User is a Non-Member (Privilege Gated)

_Branching point: At Step 2 of the Basic Flow, if the student does not hold an active membership subscription._

1. The **System** detects that the user has non-member status (`can_reserve = false` per `POL-03` and `POL-07`).
2. The **System** replaces the "Reserve" button with a disabled button and displays: _"Reservations are exclusive to library members."_
3. The **System** presents a secondary action link: "Become a Member (`UC-05`)" alongside the alternative "Notify me when available (`UC-08 Wishlist`)".
4. The student can click to explore membership plans or opt for basic wishlist notification.
5. The use case ends without creating a reservation.

#### 2.2.2 Reservation Queue Full (Max 5 Waiting per Title)

_Branching point: At Step 2 of the Basic Flow, if 5 members are already waiting in the reservation queue for the book._

1. The **System** determines that the count of reservations in `waiting` status for the `book_id` has reached 5.
2. The **System** disables the "Reserve" button and displays the notification: _"Reservation queue is full (maximum 5 members in line). Please check back later or add to wishlist."_
3. The student can click "Add to Wishlist" (`UC-08`) to receive an alert if the title's queue empties or more copies arrive.
4. The use case ends.

#### 2.2.3 User Reservation Quota Reached (Max 3 Active Reservations)

_Branching point: At Step 2 of the Basic Flow, if the student already has 3 active reservations across all titles._

1. The **System** counts active reservations (`status IN ('waiting', 'ready_for_pickup')`) associated with the student profile and finds the count equals 3.
2. The **System** disables the "Reserve" button and displays an inline notice: _"You have reached your limit of 3 concurrent active reservations."_
3. The student can navigate to `/reservations` to review or cancel an existing reservation if they wish to prioritize this book.
4. The use case ends.

#### 2.2.4 Duplicate Active Reservation or Active Loan for Same Book

_Branching point: At Step 2 of the Basic Flow, if the student already holds an ongoing loan, cart checkout, or existing reservation for the same book._

1. The **System** checks active records and finds a matching `book_id` in `loan_items` (statuses `awaiting_payment`, `ready_for_pickup`, `borrowed`, `overdue`) or `reservations` (`waiting`, `ready_for_pickup`).
2. The **System** disables the action and returns error code `DUPLICATE_ACTIVE_LOAN`: _"You already have this book borrowed, requested, or reserved."_
3. The use case ends.

#### 2.2.5 Student Under Reservation Ban or Debt Hold

_Branching point: At Step 2 of the Basic Flow, if the student has accrued 3 reservation strikes or has an outstanding debt hold._

1. If the student is under a reservation ban (`reservation_ban_until > NOW()` resulting from 3 uncollected pickup expirations per `POL-07` and `FR-RES-03`):
   - The **System** disables the reserve action and displays: _"Reservation privileges suspended until [Ban End Date] due to 3 uncollected pickup strikes."_
2. If the student has a debt hold (`debt_hold = true`):
   - The **System** displays: _"Reservations blocked due to outstanding balance. Please settle your charges (`UC-13`)."_
3. The use case ends.

#### 2.2.6 Book is Non-Circulating (All Copies Retired or Lost)

_Branching point: At Step 2 of the Basic Flow, if all physical copies of the book have been written off or retired (`POL-07`, `DEC-21`)._

1. The **System** queries copies of the book and finds every copy is in status `retired` or `lost`.
2. The **System** identifies the title as non-circulating.
3. The **System** disables reservation controls and displays: _"This title is currently not circulating. You may submit an acquisition suggestion (`UC-16`)."_
4. The use case ends.

#### 2.2.7 Cancelling a Waiting or Ready Reservation

_Branching point: At any time after reservation placement, when the student views their active reservations on `/reservations`._

1. The **Student** navigates to `/reservations` and locates their reservation card.
2. The **Student** clicks the "Cancel Reservation" button (`FR-RES-04`).
3. The **System** presents a confirmation modal stating that cancelling a reservation voluntarily carries zero penalty and incurs no strike.
4. The **Student** confirms cancellation.
5. The **System** updates the reservation status to `cancelled`:
   - If the reservation was in `waiting` status, remaining members in the queue have their relative positions recalculated.
   - If the reservation was in `ready_for_pickup` status, the held copy is immediately released and evaluated for promotion to the next waiting member in line (or returned to `available` status if the queue is empty).
6. The **System** displays a confirmation toast and updates the reservations list. The use case ends.

## 3. Special Requirements

### 3.1 First-Come First-Served Queue Fairness

- The reservation queue must strictly adhere to FIFO ordering based on creation timestamp (`created_at`).
- Staff or administrators cannot reorder the queue or insert priority entries (`FR-RES-05`).

### 3.2 Automated Promotion and 48-Hour Pickup Window

- When a borrowed copy is returned (`UC-21`), the backend trigger immediately checks for the highest-priority `waiting` reservation for that title.
- If found, the copy status is set to `held`, the reservation status transitions to `ready_for_pickup`, and a 48-hour deadline (`expires_at = NOW() + 48 hours`) is stamped.
- If the student fails to collect the book within 48 hours, the system cancels the reservation, records a strike on the student's profile, and automatically promotes the next eligible reservation in queue.

### 3.3 Real-time Queue Updates and Notifications

- Any state transition (advancing queue position, copy becoming ready for pickup, cancellation) must trigger instant push updates via Supabase Realtime and dispatch email notifications to the student.

## 4. Preconditions

### 4.1 Active Membership Entitlement

The Student is authenticated and possesses an active membership plan granting reservation privileges (`can_reserve = true`).

### 4.2 Zero Currently Available Copies

The selected book record has no copies currently in `available` status on library shelves.

---

## 5. Postconditions

### 5.1 Reservation Created

- A new `reservations` record is created in `waiting` state with a valid queue position.
- The student's active reservation count increases by 1.
- The title's queue depth counter increments on the Book Detail page.

### 5.2 Reservation Request Blocked

- No reservation record is created.
- The user is presented with the specific reason for denial (e.g., non-member, queue full, limit reached, ban, debt).

## 6. Extension Points

### 6.1 Extension to Manage Membership (UC-05)

- **Condition:** Non-member student wishes to unlock reservation privileges.
- **Location:** Step 3 of Alternative Flow 2.2.1. Navigates to `UC-05 - Manage membership` to purchase a plan.

### 6.2 Extension to Manage Book Wishlist (UC-08)

- **Condition:** Non-member or member encountering a full queue opting for general stock notification.
- **Location:** Step 3 of Alternative Flow 2.2.1 or Step 3 of Alternative Flow 2.2.2. Invokes `UC-08 - Manage a book wishlist`.
