## 1. Use-Case Name

**UC-06 - Discover and inspect books** (Traces to: `FEAT-04`, `FEAT-05`, `POL-17`, `FR-SRCH-01`, `FR-SRCH-02`, `FR-SRCH-03`, `FR-SRCH-04`, `FR-SRCH-05`)

### 1.1 Brief Description

This use case enables a Student (Reader) or prospective user to discover titles within the library catalog through keyword search, curated browsing collections (New Arrivals, Top Books), multi-attribute filtering, and custom sorting. Once a relevant title is selected, the user inspects comprehensive book details, including bibliographic metadata, table of contents, collection classification (Standard or Premium), real-time shelf location, real-time physical copy availability, average user ratings, and returned student reviews. Based on real-time availability and the user's active membership privileges, the system presents actionable buttons such as "Add to Cart", "Reserve", or "Notify Me".

### 1.2 Actors

- **Primary Actor:** Student (Reader) / Unauthenticated Visitor
- **Supporting Systems:** Supabase PostgreSQL Database (Full-Text Search, pg_trgm, unaccent RPCs, Realtime subscriptions)

## 2. Flow of Events

### 2.1 Basic Flow

This use case begins when a **Student** navigates to the library discovery or catalog section (`/search` or `/browse`).

1. The **Student** enters search terms (e.g., title keywords, author name, subject keyword, or 10/13-digit ISBN) into the global search bar on the Discovery page (`/search`).
2. The **System** debounces input by 250 ms, normalizes the query string according to Unicode NFC, strips punctuation and ISBN hyphens, and invokes the PostgreSQL search RPC (`search_books`).
3. The **System** performs two-tier matching:
   - Candidates are identified via accent-insensitive matching and trigram similarity (`pg_trgm`).
   - Results are ranked according to relevance rules: exact ISBN match first, followed by count of accent-exact token matches, weighted field scores (Title: 3, Authors: 2, Keywords: 2), and catalog popularity (`POL-17`).
4. The **System** displays a paginated list of matching book cards (20 items per page). Each card displays the cover thumbnail, title, authors, collection badge (Standard vs. Premium), live availability chip (e.g., "3 of 5 copies available"), average star rating, and review count.
5. The **Student** applies optional filter criteria (e.g., Category: "Computer Science", Collection: "Standard", Availability: "Available Now") and selects a sort order (e.g., "Rating: High to Low").
6. The **System** applies the filters, re-orders the candidate set, synchronizes the URL search query parameters, and refreshes the book results.
7. The **Student** clicks on a specific book card.
8. The **System** navigates to the Book Detail page (`/books/:bookId`).
9. The **System** loads and renders the full bibliographic metadata:
   - Title, subtitle, author(s), publisher, publication year, edition, language, category, and field.
   - Normalized ISBN-10 and ISBN-13.
   - Synopsis / Description and expandable Table of Contents.
   - Collection type (Standard or Premium) and applicable non-member borrowing fee.
   - Physical shelf location (Zone, Bookcase, Shelf row, e.g., "CS-B2-S04").
   - Live inventory status (total copies, available copies, copies currently held or checked out).
   - Aggregate reader rating, star distribution chart, and paginated student reviews.
10. The **System** evaluates the student's active session, debt status, and current entitlements, displaying the appropriate context-sensitive action button:
    - If at least one copy is `available` and the student has not exceeded their borrowing limit, the **System** enables the "Add to Cart" button.
    - If zero copies are available, the **System** presents "Reserve Book" (for active members) or "Notify Me When Available" (Wishlist for non-members or when queues are open).
11. The **Student** inspects the bibliographic and availability details. The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 No Matching Books Found

_Branching point: At Step 3 of the Basic Flow, if no catalog records match the query terms or filter criteria._

1. The **System** renders a clear empty state message: _"No books matched your search criteria."_
2. The **System** displays actionable remediation links:
   - "Clear All Filters" to reset active filters.
   - "Ask AI Research Assistant" linking to `/assistant` with the search query pre-populated.
   - "Suggest a New Book Purchase" linking to the Book Suggestion form (`/suggestions`) with title keywords prefilled.
3. The **Student** may adjust search parameters or proceed with a recommendation/suggestion option. The flow resumes at Step 1 or terminates.

#### 2.2.2 Category and Dependent Field Filtering

_Branching point: At Step 5 of the Basic Flow, when the student changes the primary Category filter._

1. The **Student** selects a new primary Category (e.g., from "Information Technology" to "Natural Sciences").
2. The **System** dynamically updates the available options in the secondary "Field" dropdown to correspond strictly with the newly chosen category.
3. If the previously selected Field does not belong to the newly chosen Category, the **System** automatically resets the Field selection to "All Fields".
4. The flow resumes at Step 6 of the Basic Flow.

#### 2.2.3 Real-Time Stock Depletion on Detail Page

_Branching point: While the Student is viewing the Book Detail page at Step 9, the final available physical copy is checked out or placed on hold by another user._

1. The **System** receives a Supabase Realtime broadcast indicating that the available copy count for the current `bookId` has transitioned to 0.
2. The **System** dynamically updates the availability badge from "1 copy available" to "Currently Unavailable" without requiring a full page refresh.
3. The **System** disables the "Add to Cart" button, replacing it with either "Reserve Book" (if the student is an eligible member) or "Add to Wishlist / Notify Me" (if non-member or queue conditions apply).
4. A non-intrusive toast notification informs the student: _"Stock updated: The last available copy of this title was just claimed by another patron."_
5. The flow resumes at Step 10 of the Basic Flow.

#### 2.2.4 Book Draft or Unpublished Status

_Branching point: At Step 8 of the Basic Flow, if the requested `bookId` is in draft status, deleted, or invalid._

1. The **System** validates catalog record visibility.
2. The **System** responds with an HTTP 404 Not Found status and presents a friendly error screen: _"Book record not found or not currently circulating."_
3. The **System** displays a button allowing the student to return to the catalog search page (`/search`). The use case ends.

## 3. Special Requirements

### 3.1 Search Matching and Vietnamese Diacritics Ranking

- All queries and catalog text must be normalized using Unicode NFC. The search engine must support both accented and unaccented Vietnamese search seamlessly (`POL-17`).
- Queries with explicit diacritics (e.g., `hóa`) must return candidates matching accent-insensitively, but rank exact diacritic matches (`hóa`) strictly higher than other diacritic variations (`họa`, `hoa`).
- ISBN searches must match both 10-digit and 13-digit standards with all hyphens and whitespace stripped.

### 3.2 Performance, Caching, and Debouncing

- Search keystroke events must be debounced client-side by 250 ms to minimize database load.
- The search RPC execution time must not exceed 200 ms for catalog collections of up to 50,000 titles.
- Query parameters (`q`, `category`, `field`, `collection`, `sort`, `page`) must synchronize bidirectionally with the browser URL to support browser history, back/forward navigation, and shareable links.

### 3.3 Accessibility and Screen Reader Support

- Filter sidebars and result cards must adhere to WCAG 2.1 Level AA standards, featuring descriptive `aria-label` tags, live regions (`aria-live="polite"`) for result counters, and full keyboard navigation.

## 4. Preconditions

### 4.1 Catalog Data Availability

The ShelfHelp PostgreSQL database and search functions are online and populated with published book records and inventory copies.

### 4.2 User Session State

The user may be an unauthenticated guest or an authenticated student. (Guests can search and inspect book metadata; actionable operations such as Cart, Reservation, or Wishlist require authentication).

---

## 5. Postconditions

### 5.1 Book Inspected

- The user has inspected the book's bibliographic attributes, availability, location, and ratings.
- The view count / popularity metrics of the inspected book are recorded for analytics.

### 5.2 Search Parameters Preserved

- The search state, active filter set, and pagination position remain preserved in the browser URL and state store.

## 6. Extension Points

### 6.1 Barcode Scanning Extension

- At Step 1, the student may invoke `UC-07 (Find a book by barcode)` to scan an ISBN barcode via their device camera, jumping directly to Step 9 (Book Detail).

### 6.2 Borrowing Cart Addition

- At Step 10, if an available copy exists, the student may select `UC-09 (Manage borrowing cart)` to add the book to their cart.

### 6.3 Reservation Queue Placement

- At Step 10, if zero copies are available and the student holds an active membership, the student may invoke `UC-14 (Reserve an unavailable book)`.

### 6.4 Wishlist Notification Toggle

- At Step 10, if zero copies are available, the student may invoke `UC-08 (Manage a book wishlist)` to register for automated availability alerts.
