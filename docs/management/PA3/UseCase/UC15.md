## 1. Use-Case Name

**UC-15 - Rate and review a returned book** (Traces to: `FEAT-12`, `POL-14`, `FR-LOAN-04`)

### 1.1 Brief Description

This use case allows a Student (Reader) who has physically borrowed and successfully returned a book to submit a star rating (1 to 5 stars) and an optional written review (up to 1,000 characters). This mechanism implements the "Verified Reader" integrity model (`POL-14`), ensuring that only students with a completed loan record for a title can rate or review it. Submissions instantly update the book's overall rating average, rating distribution histogram, popularity metrics, and AI recommendation weighting. Students can also edit their existing review directly from the Book Detail page.

### 1.2 Actors

- **Primary Actor:** Student (Reader)
- **Supporting Actor:** None

---

## 2. Flow of Events

### 2.1 Basic Flow (Submitting a New Rating & Review)

This flow occurs either immediately after staff processes a book return at the desk (prompted via notification or dialog in "My Loans"), or when the student opens the Book Detail page of a returned title.

1. The **Student** receives a return confirmation prompt on their "My Loans" page (`/loans`), opens a "Rate your recent read" in-app notification, or navigates to the Book Detail page (`/books/:bookId`) of a title they have previously returned.
2. The **System** verifies that:
   - The student has at least one loan record for this `book_id` in `returned` status.
   - The student has not yet submitted an active review for this title.
3. The **System** displays the "Rate & Review" modal or interactive inline form containing:
   - Book cover, title, and authors.
   - Interactive 5-star rating selector (1 to 5 stars, mandatory).
   - Textarea for written feedback (optional, with a live countdown counter: 0 / 1,000 characters).
   - "Submit Review" button and a "Skip / Later" button.
4. The **Student** selects a star rating (e.g., 5 stars) and optionally types descriptive feedback about the book.
5. The **Student** clicks the "Submit Review" button.
6. The **System** validates input constraints client-side and server-side:
   - Star rating is an integer between 1 and 5.
   - Review text length does not exceed 1,000 characters.
7. The **System** inserts a new record into the `reviews` table containing:
   - `book_id`, `user_id`, `rating`, `comment`, `created_at = NOW()`, `updated_at = NOW()`.
8. The **System** re-computes the book's aggregate rating statistics:
   - Updates `rating_average` and `rating_count` on the `books` table.
   - Re-indexes the rating metrics for semantic AI recommendation scoring (`POL-15`, `POL-17`).
9. The **System** displays a thank-you confirmation toast: _"Thank you for your feedback! Your review has been published."_
10. The **System** updates the Book Detail page and displays the student's review under the "Community Reviews" tab with an "Edit Review" button. The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 Editing an Existing Review

_Branching point: At Step 2 of the Basic Flow, if the student has previously submitted a review for this book._

1. The **System** detects an existing `reviews` row for the `(book_id, user_id)` tuple.
2. On the Book Detail page (`/books/:bookId`), the **System** displays the student's existing rating and review with an "Edit Review" button.
3. The **Student** clicks "Edit Review".
4. The **System** opens the review dialog pre-populated with the current star rating and review text.
5. The **Student** modifies the star rating and/or edits the text, then clicks "Save Changes".
6. The **System** validates the modified content and updates the existing `reviews` record (`updated_at = NOW()`).
7. The **System** re-aggregates the book's average rating and distribution.
8. The **System** displays a toast confirmation: _"Your review has been updated."_
9. The use case ends.

#### 2.2.2 Student Skips or Dismisses Review Prompt

_Branching point: At Step 3 of the Basic Flow, if the student does not wish to provide a review._

1. The **Student** clicks "Skip" or dismisses the review dialog modal.
2. The **System** closes the modal without creating any review or rating record.
3. The **System** records a dismissal flag in local session storage so the intrusive pop-up dialog is not re-displayed immediately for this loan item.
4. The option to rate and review remains accessible on-demand from the Book Detail page whenever the student chooses.
5. The use case ends.

#### 2.2.3 Attempting to Review an Unborrowed Book

_Branching point: At Step 1 of the Basic Flow, if a student navigates to a Book Detail page for a book they have never borrowed and returned._

1. The **System** queries `loan_items` for the student and `book_id` and finds no record with `status = 'returned'`.
2. The **System** hides the "Write a Review" button and star-rating input.
3. The **System** renders the community reviews list in read-only mode, displaying an informative caption: _"Only verified readers who have borrowed and returned this book may submit a rating."_
4. The use case ends.

#### 2.2.4 Validation Error (Character Limit Exceeded or Empty Rating)

_Branching point: At Step 5 of the Basic Flow, if the user submits without selecting a star rating or exceeds 1,000 characters._

1. The **System** identifies the validation violation:
   - If no star rating was chosen: displays inline alert _"Please select a rating between 1 and 5 stars."_
   - If the comment exceeds 1,000 characters: highlights the textarea and displays _"Review exceeds the maximum length of 1,000 characters."_
2. The **System** prevents submission and keeps the entered text intact.
3. The **Student** selects a star rating or trims the text to within limits.
4. The flow resumes at Step 5 of the Basic Flow.

## 3. Special Requirements

### 3.1 Verified Reader Rule

- Rating and review submission permissions are strictly enforced at the database level via PostgreSQL Row-Level Security (RLS) and stored function checks (`POL-14`).
- Users who have only requested, wishlisted, or currently hold a book on loan cannot rate it until the physical return has been registered and verified by staff (`status = 'returned'`).

### 3.2 Real-time Aggregation and Popularity Impact

- Aggregates (`rating_average`, `rating_count`, and the 1-to-5 star breakdown) must be updated efficiently upon insert or edit.
- Search sorting by rating (`FR-SRCH-03`) and AI assistant recommendations (`FR-AI-05`) must incorporate updated ratings within their ranking algorithm.

### 3.3 Content Integrity and Moderation Scope

- Reviews must be stored as plain UTF-8 text with automatic escaping to prevent Cross-Site Scripting (XSS).
- The current system scope supports one review per student per book, editable by the owner, with basic text sanitization (`POL-14`).

---

## 4. Preconditions

### 4.1 Loan Returned Verification

The Student has an authenticated profile and possesses a documented historical loan in `returned` status for the target book.

### 4.2 Authenticated Reader

The user is signed into an active ShelfHelp session with the `student` role.

---

## 5. Postconditions

### 5.1 Review Persisted and Metrics Recalculated

- A row in `reviews` exists with the verified user's rating (1–5) and optional comment text.
- The book's average star rating and count are updated.
- The review is immediately visible to other library patrons browsing the book.

### 5.2 Review Dialog Dismissed

- If skipped, no database modifications occur, and the student retains eligibility to submit a review in the future.
