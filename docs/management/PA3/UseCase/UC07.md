## 1. Use-Case Name

**UC-07 - Find a book by barcode** (Traces to: `FEAT-06`, `FR-SRCH-07`, `DEC-35`)

### 1.1 Brief Description

This use case provides an alternate, streamlined entry point to catalog discovery. It allows a Student (Reader) or patron to scan a printed EAN-13 ISBN barcode on a physical book using their mobile device or laptop camera. Upon scanning, the system decodes the barcode, verifies the ISBN checksum, and opens the corresponding catalog record detail page (`/books/:bookId`). If the scanned ISBN is not in the library collection, the system informs the user and offers to prefill a new book acquisition suggestion form (`UC-16`). When camera hardware is unavailable or permissions are denied, the system seamlessly falls back to a manual ISBN input field.

### 1.2 Actors

- **Primary Actor:** Student (Reader) / Library Patron
- **Supporting Systems:** Client Browser MediaDevices / WebRTC API, Client-Side Barcode Detection Engine (Barcode Detection API / ZXing-Wasm)

## 2. Flow of Events

### 2.1 Basic Flow

This use case begins when a **Student** taps the Barcode Scanner icon on the Home dashboard (`/`) or Catalog Search page (`/search`).

1. The **Student** clicks or taps the "Scan Barcode" button in the search interface.
2. The **System** displays the Barcode Scanner modal overlay.
3. The **System** requests user permission to access the device's video capture camera via the browser `navigator.mediaDevices.getUserMedia` API.
4. The **Student** grants camera permission.
5. The **System** initializes the rear-facing camera stream (if on mobile) and renders an active viewfinder window with a visual scanning targeting reticle.
6. The **Student** aligns the physical book's printed ISBN barcode (EAN-13, starting with 978 or 979) within the targeting guide.
7. The **System** continuously captures frames and feeds them to the client-side barcode decoding worker.
8. The **System** detects and decodes the EAN-13 barcode, plays a subtle audible confirmation beep (or haptic vibration on supported mobile devices), and validates the ISBN-13 checksum algorithm (modulo 10 check digit).
9. The **System** immediately shuts down the camera video stream and releases media hardware tracks.
10. The **System** queries the catalog database for an active book record matching the normalized ISBN.
11. The **System** finds the matching catalog record, closes the scanner modal, and navigates the student directly to the Book Detail page (`/books/:bookId`). The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 Camera Permission Denied or Unavailable

_Branching point: At Step 3 or Step 4 of the Basic Flow, if the user denies camera permission, no camera hardware is detected, or the connection is unencrypted (non-HTTPS)._

1. The **System** detects that camera access is blocked or unavailable.
2. The **System** displays an explanatory alert in the scanner dialog: _"Camera access is unavailable. Please check browser permissions, or enter the ISBN manually below."_
3. The **System** renders an inline manual input field for `ISBN-10 or ISBN-13` accompanied by a "Find Book" button.
4. The **Student** types the 10-digit or 13-digit ISBN and clicks "Find Book".
5. The **System** validates the entered digits and checksum.
6. The flow resumes at Step 10 of the Basic Flow.

#### 2.2.2 Scanned Barcode Invalid or Corrupted

_Branching point: At Step 8 of the Basic Flow, if the scanned barcode decodes to an invalid number or fails the EAN-13 checksum._

1. The **System** determines that the barcode checksum is invalid or represents an unsupported barcode symbology (e.g., non-book UPC or damaged code).
2. The **System** momentarily flashes a red reticle indicator in the viewfinder with the guidance message: _"Unrecognized or invalid ISBN barcode. Please align clearly or enter manually."_
3. The camera stream remains active.
4. The **Student** realigns the barcode or switches to manual entry. The flow returns to Step 6 of the Basic Flow.

#### 2.2.3 Scanned ISBN Not in Library Catalog

_Branching point: At Step 11 of the Basic Flow, if the scanned ISBN is valid but does not correspond to any title in the ShelfHelp catalog._

1. The **System** shuts down the camera stream and displays an informational modal: _"Book Not in Catalog: ISBN [Scanned ISBN] is not currently in the library collection."_
2. The **System** presents two actionable options:
   - "Suggest this Book for Purchase": Navigates the student to the Book Suggestion form (`/suggestions`, `UC-16`) with the `ISBN` field pre-populated.
   - "Scan Another Book": Reopens the scanner viewfinder to scan a different title.
3. The **Student** selects their desired option, and the flow branches accordingly or ends.

#### 2.2.4 Scanner Modal Dismissed by User

_Branching point: At any point prior to successful detection, if the user clicks the "Close" (X) button, presses the Escape key, or clicks outside the modal._

1. The **Student** initiates modal dismissal.
2. The **System** immediately invokes `MediaStreamTrack.stop()` on all active video tracks, releasing device camera hardware.
3. The **System** closes the scanner dialog, returning the student to their prior screen (`/` or `/search`). The use case ends.

## 3. Special Requirements

### 3.1 Hardware and Camera Stream Lifecycle

- The camera video stream must be strictly contained within the modal lifecycle. The system must release camera hardware instantly upon barcode detection, modal dismissal, backgrounding the browser tab, or component unmounting, ensuring privacy indicators on mobile devices and laptops switch off promptly (`FR-SRCH-07`).

### 3.2 Barcode Recognition and Decoding Performance

- The client-side decoder must identify and decode crisp EAN-13 barcodes within 2.0 seconds of proper reticle alignment under standard indoor library lighting.
- The decoding engine must run in a background Web Worker or use native browser `BarcodeDetector` when available to prevent main-thread UI frame stutter.

### 3.3 Security and HTTPS Requirement

- Camera access requires a secure context (HTTPS or localhost). In insecure HTTP environments, the system must gracefully disable the camera option and present the manual entry interface without throwing unhandled exceptions.

## 4. Preconditions

### 4.1 Device and Network Capability

The user is operating a device with modern browser capabilities and network connectivity to the ShelfHelp application.

## 5. Postconditions

### 5.1 Book Located and Detail Opened

- The target book is located by ISBN and the Book Detail view (`UC-06`) is rendered on screen.

### 5.2 Camera Resources Released

- All camera streams and hardware locks are completely terminated and freed.

## 6. Extension Points

### 6.1 Direct Transition to Book Inspection

- Extends `UC-06 (Discover and inspect books)` by serving as an automated visual entry point directly to the Book Detail view (`/books/:bookId`).

### 6.2 Direct Transition to Book Suggestion

- If the book is absent from the catalog, branches to `UC-16 (Manage book suggestions)` with prefilled ISBN data.
