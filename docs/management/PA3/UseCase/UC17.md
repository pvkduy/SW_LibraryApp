## 1. Use-Case Name

**UC-17 - Get research recommendations** (Traces to: `FEAT-26`, `POL-15`, `FR-AI-01`, `FR-AI-02`, `FR-AI-05`)

### 1.1 Brief Description

This use case enables an authenticated Student (Reader) to converse with the ShelfHelp AI Research Assistant (`/assistant`) in natural language (Vietnamese or English) to discover relevant academic literature, textbooks, and monograph references for their coursework or thesis. Powered by Retrieval-Augmented Generation (RAG) coupled with pgvector semantic similarity search, the assistant analyzes the student's research query, retrieves semantically relevant catalog items, and synthesizes structured recommendations. Responses include contextual explanations, suggested pedagogical reading orders (e.g., beginner foundational works followed by advanced monographs), follow-up prompt chips, and interactive book cards with live availability, shelf call numbers, and direct borrowing or reservation action buttons.

### 1.2 Actors

- **Primary Actor:** Student (Reader)
- **Supporting Actor:** AI Provider (Google Gemini API / OpenAI LLM Service & Embedding Model)

## 2. Flow of Events

### 2.1 Basic Flow (Conversational Research Recommendation)

1. The **Student** navigates to the AI Assistant screen (`/assistant`) or clicks the "Ask AI Assistant" shortcut from the home screen or search empty-state.
2. The **System** displays the conversational chat interface:
   - Sidebar with existing conversation threads and a "New Chat" button.
   - Main message container configured as an ARIA live region.
   - Quick starter prompt chips (e.g., _"Recommend introductory books for Machine Learning"_, _"I need resources for Software Architecture patterns"_).
   - Message input textarea (max 1,000 characters) with a "Send" button.
3. The **Student** enters a research inquiry describing their topic, learning level, or research thesis focus (e.g., _"I am writing a thesis on distributed systems consensus algorithms; what books should I read first?"_) and clicks "Send".
4. The **System** performs client-side validation, creates a user message in the current conversation, disables the input box, and displays an animated typing indicator.
5. The **System** processes the request through the backend AI pipeline (`POL-15`, `FR-AI-02`):
   - Generates text embeddings for the student's query.
   - Executes semantic vector similarity search via `pgvector` against catalog book summaries, tables of contents, and subject keywords.
   - Filters retrieved books to include only active catalog titles.
   - Constructs a grounded prompt containing the top matched book metadata and system instructions.
6. The **AI Provider** generates a natural-language response synthesizing the recommendations:
   - Formulates a structured pedagogical reading sequence (Foundational -> Advanced).
   - Explains why each title is relevant to the student's thesis topic.
   - Generates 2 to 3 contextual follow-up prompt chips.
7. The **System** combines the synthesized text with live inventory data from the database and renders the response in the chat thread:
   - Interactive book cards displaying cover thumbnail, title, authors, level badge (Beginner, Intermediate, Advanced), average rating, and physical shelf location.
   - Live availability badge showing available copies.
   - Context-sensitive action button: "Add to Cart" (if available), "Reserve" (if unavailable and user is a member), or "Notify Me" (wishlist).
   - Follow-up query chips below the message.
8. The **System** persists the conversation exchange in `ai_conversations` and `ai_messages` tables.
9. The **System** re-enables the message input box and updates the hourly rate limit quota indicator. The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 No Relevant Catalog Holdings Found (Fallback to Suggestion)

_Branching point: At Step 5 of the Basic Flow, if vector similarity search yields no book records exceeding the relevance threshold._

1. The **System** detects that the library collection contains no relevant holdings matching the specific inquiry.
2. The **AI Provider** formats an honest fallback explanation: _"The library currently does not have specialized holdings covering this specific subtopic."_
3. The **System** renders a fallback suggestion prompt:
   - Displays a prominent call-to-action button: _"Suggest this book/topic to the library (`UC-16`)"_.
4. The **Student** clicks "Suggest this book".
5. The **System** redirects the student to the suggestion form (`/suggestions`), pre-filling the `Title` and `Reason` fields using the context extracted from the conversation.
6. The flow transitions to `UC-16 - Manage book suggestions`.

#### 2.2.2 Hourly Rate Limit Exceeded

_Branching point: At Step 4 of the Basic Flow, if the student exceeds the allocated conversational rate limit (e.g., 20 messages per hour per `POL-15` and `FR-AI-01`)._

1. The **System** queries recent message timestamps and determines that the student has sent 20 messages within the rolling 60-minute window.
2. The **System** rejects message dispatch and displays an inline banner: _"Hourly message limit reached (20/20). To ensure fair access for all students, please wait until [Reset Time] before sending your next inquiry."_
3. The message text remains preserved in the input box so the student does not lose their typed query.
4. The use case ends.

#### 2.2.3 Input Exceeds Maximum Character Limit (1,000 Chars)

_Branching point: At Step 3 of the Basic Flow, if the student pastes or types a prompt exceeding 1,000 characters._

1. The **System** highlights the character counter in warning red: _"1,045 / 1,000 characters"_.
2. The "Send" button is disabled.
3. The **Student** edits or trims their prompt to 1,000 characters or fewer.
4. The "Send" button re-enables, and the flow resumes at Step 3 of the Basic Flow.

#### 2.2.4 Managing Chat Sessions (New Conversation / Clear History)

_Branching point: At Step 2 of the Basic Flow, when the student wants to organize their conversation history._

1. The **Student** views previous research threads in the sidebar.
2. The **Student** can:
   - Click "New Chat" to start a fresh context, resetting the conversational memory buffer.
   - Click the "Delete" trash icon next to a past thread to delete the stored conversation and its associated messages.
3. The **System** confirms deletion and removes the conversation rows from PostgreSQL.
4. The use case completes.

#### 2.2.5 Direct Action Execution from Book Cards

_Branching point: At Step 7 of the Basic Flow, when the student interacts with a recommended book card._

1. The student inspects a recommended book card within the chat stream.
2. Depending on book availability and student status:
   - If available: student clicks "Add to Cart", invoking `UC-09 - Manage borrowing cart`.
   - If unavailable and student is a member: student clicks "Reserve", invoking `UC-14 - Reserve an unavailable book`.
   - If user wants to inspect details: student clicks the book title or cover, navigating to the full Book Detail page (`/books/:bookId`).
3. The action executes smoothly without disrupting the ongoing conversation context.

## 3. Special Requirements

### 3.1 RAG Grounding and Anti-Hallucination Guardrails

- The AI assistant must strictly ground book citations in actual catalog items present in the ShelfHelp database (`POL-15`).
- The assistant is forbidden from hallucinating fictional call numbers, ISBNs, or non-existent library holdings. If a title is not in the database, it must explicitly recommend submitting an acquisition request (`UC-16`).

### 3.2 Real-time Context and Live Inventory Integration

- While the conversational text is synthesized by the LLM, book availability chips (e.g., "2 of 3 copies available", shelf location "Shelf CS-04") must be injected dynamically from current database state at rendering time to ensure real-time accuracy.

### 3.3 Accessibility and Performance

- The chat container must employ ARIA live regions (`aria-live="polite"`) so that screen readers announce newly arrived assistant messages.
- Vector search and initial response streaming should initiate within 1.5 seconds under standard network conditions.

## 4. Preconditions

### 4.1 System and AI Service Operational

The ShelfHelp backend, pgvector extension, and external AI Provider (Gemini API) are reachable and configured with valid API keys.

### 4.2 Authenticated or Permitted Student Session

The Student is authenticated with an active or restricted profile (restricted students may still query the AI assistant in read-only mode per `POL-02` and `DEC-19`).

---

## 5. Postconditions

### 5.1 Conversation Persisted and Recommendations Rendered

- A conversation thread and associated prompt-response messages are persisted in PostgreSQL.
- Recommended books are displayed with direct catalog links and contextual reading sequence notes.
- Hourly rate limit usage counters are updated.

### 5.2 Rate-Limited or Error State Handled

- If rate-limited or external API is unavailable, the user receives clear explanatory messaging without loss of typed input.

## 6. Extension Points

### 6.1 Extension to Manage Book Suggestions (UC-16)

- **Condition:** AI Assistant retrieves zero relevant catalog holdings for an esoteric research inquiry.
- **Location:** Step 3 of Alternative Flow 2.2.1. Navigates to `UC-16 - Manage book suggestions` with prefilled research topic data.

### 6.2 Extension to Manage Borrowing Cart (UC-09)

- **Condition:** Student adds an available recommended book directly to their cart.
- **Location:** Step 2 of Alternative Flow 2.2.5. Invokes `UC-09 - Manage borrowing cart`.

### 6.3 Extension to Reserve an Unavailable Book (UC-14)

- **Condition:** Student reserves a checked-out recommended book directly from the recommendation card.
- **Location:** Step 2 of Alternative Flow 2.2.5. Invokes `UC-14 - Reserve an unavailable book`.
