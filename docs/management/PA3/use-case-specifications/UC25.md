## 1. Use-Case Name

**UC-25 - Receive an acquisition shipment** (Traces to: `FEAT-20`, `FEAT-22`, `FR-SUGG-07`, `FR-SUGG-08`, `FR-SUGG-09`, `FR-INV-04`, `FR-INV-05`, `FR-RES-02`, `POL-12`)

### 1.1 Brief Description

This use case enables a **Librarian (Admin)** to mark titles in an ordered acquisition batch as received (delivered). A batch is a hand-created tracking checklist: each line is a title with an expected quantity, and the activity is marking a title as received, with an optional target shelf staging location and an optional discrepancy/condition note. Marking a line received makes its copies `available` via `batch_receipt` inventory transactions and records who marked which title received. A batch is closed automatically when every line is received.

### 1.2 Actors

- **Primary Actor:** Librarian (Admin)
- **Supporting Actor:** Book Vendor / Courier (External physical delivery agent), Notification Service

---

## 2. Flow of Events

### 2.1 Basic Flow

This use case begins when a batch title has been delivered and an authenticated **Librarian (Admin)** marks it received in the batch checklist.

1. The **Librarian** navigates to the Acquisitions Batches section at `/admin/batches` and selects a batch in `ordered` status.
2. The **System** presents the Batch Detail screen (`/admin/batches/:id`) using the standard table–detail panel: each row lists a title and its expected quantity, with a received/delivered state.
3. The **Librarian** selects the title that has been delivered and clicks "Mark Received".
4. The **System** prompts for an optional **target shelf staging location** and an optional **discrepancy/condition note**.
5. The **Librarian** confirms.
6. The **System** marks the line `received`, makes the title's copies `available` (via `batch_receipt` inventory transactions), records **who** marked the title received in the activity history, and notifies the relevant requesters (`FR-SUGG-09`).
7. When every line in the batch is marked received, the **System** automatically closes the batch. The use case ends.

### 2.2 Alternative Flows

#### 2.2.1 Receiving a Title Not Yet in the Library Catalog

_Branching point: At Step 3 of the Basic Flow, if the delivered title has no bibliographic record in the catalog._

1. The **System** detects the title is not cataloged and prompts the Librarian to create the book record first (`FR-SUGG-07`).
2. The **Librarian** completes the Book editor (prefilled from the batch line) and saves.
3. The flow resumes at Step 5 of the Basic Flow.

#### 2.2.2 Batch Closed Automatically

_Branching point: At Step 7 of the Basic Flow, when the last unreceived line is marked received._

1. The **System** detects all lines are `received` and sets the batch status to `closed`. No manual close action exists.

---

## 3. Special Requirements

### 3.1 Transaction Atomicity and Inventory Provenance

- Marking a line received, creating copies, logging `batch_receipt` inventory transactions, and recording the activity entry must occur in one atomic transaction (`FR-SUGG-07`).

### 3.2 No Hard Deletion Policy

- Batches, batch lines, and copies are never deleted.

### 3.3 Notification Delivery and Idempotency

- Requesters are notified once per event (`FR-SUGG-09`), idempotently.

### 3.4 Role-Based Access Control

- Only the `admin` role can mark lines received (`FR-AUTH-05`).

---

## 4. Preconditions

### 4.1 Staff Authentication

The Librarian is logged in with acquisition and inventory privileges.

### 4.2 Ordered Batch Existence

A batch exists with status `ordered`.

---

## 5. Postconditions

### 5.1 Line Received and Copies Activated

- The line is `received`; its copies become `available` with unique barcodes.
- `batch_receipt` transactions are committed; the activity history records who marked it received.
- Suggestions update to `received`; requesters are notified; queues promote if applicable.
- If all lines are received, the batch is `closed`.

### 5.2 Receiving Aborted

- If the modal is closed without confirmation, no copies are created and the line stays `pending`.

---

## 6. Extension Points

### 6.1 Automatic Reservation Promotion on New Physical Copies

- **Location:** Step 8 of Basic Flow.
- **Trigger:** When newly received copies transition to `available` and the book title has waiting reservations (`queue_length > 0`).
- **Behavior:** The system invokes the automated reservation promotion engine (`FR-RES-02`), allocating available copies to waiting students in queue priority order, setting reservations to `ready_for_pickup`, copy statuses to `held`, setting 48-hour pickup deadlines, and sending pickup notifications.
